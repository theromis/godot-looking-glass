## Real and synthesized views

**Verified:** Gen Views allocates 24 real and 23 generated (`ViewCount-1`) layers, draw multiplier 23; without it, 48 real. Real views use `i/(ViewCount-1)`; generated views lie between neighbors. Begin still populates 48 matrices with 24 active views: [ScriptableRenderer.cs:1195](</Users/roman/work/Looking.Glass.Plugin.4.0.1-alpha-6.1/com.unity.render-pipelines.universal/Runtime/ScriptableRenderer.cs:1195>). This is not simply “24 + 24”: no 24th generated layer exists.

**Source risk, not reproduced failure:** QuiltCopy emits 48 tiles and uses generated `view/2` for odd views: tile 47 selects layer 23, while only 0–22 exist: [QuiltCopy.shader:58](</Users/roman/work/looking-glass-reference/Assets/Looking Glass Plugin/Shaders/QuiltCopy.shader:58>) (58–75). Needs Unity capture of the last tile; out-of-range behavior is API-dependent. Boundary-layer selection means static source alone cannot guarantee 48 uniformly spaced physical views.

## Expected bottlenecks and unknowns

Potential costs: geometry/fragment replication across 24–48 layers, compute scanline width, up to 80 depth reads/difficult generated pixel, DOF arrays/lenticular fullscreen work and recalibration allocations. UnsafePass hides some resources from RenderGraph; capture/barrier inspection needed. Instancing lowers CPU submissions without guaranteed GPU savings. Native sharing, pacing and Unity-versus-Godot speed unmeasured. Neural synthesis, motion/temporal reuse and native Vulkan multiview are unconfirmed in this path.
